# Migrate Trading System from Interactive Brokers to Alpaca

I want to migrate this project from **Interactive Brokers (IBKR)** to **Alpaca**.

The goal is to preserve the existing trading strategy and business logic as much as possible while replacing the broker-specific implementation with Alpaca.

## 1. Broker Migration

Replace the current Interactive Brokers integration with **Alpaca**.

Use the official Alpaca API documentation as the primary reference:

https://docs.alpaca.markets/us/reference/issuetokens

Do not assume that Alpaca's API behaves exactly like IBKR. Identify and account for any differences in:

- Authentication
- Account management
- Positions
- Cash/buying power
- Market orders
- Sell orders
- Order status
- Fractional shares
- Market hours
- Portfolio/account history
- Error handling
- API rate limits
- Paper vs. live trading

Use Alpaca Python SDK wherever possible. If an endpoint is not available in the Python SDK then make REST API calls.

# 2. Preserve the Existing Trading Strategy

The existing **buy/sell strategy must remain unchanged** unless a change is required because of an Alpaca-specific limitation.

In particular:

- `strategy.py` remains the source of the trading signals.
- Do not change the strategy logic merely as part of the broker migration.
- The broker layer should consume the signals generated by the strategy and execute the appropriate trades.

The migration should clearly separate:

**Strategy logic → Portfolio/account allocation → Broker execution**

This separation is important because I may change the broker or account configuration in the future without changing the trading strategy.

# 3. Support Multiple Alpaca Accounts

I plan to have multiple Alpaca accounts, potentially including:

- Regular taxable account
- Traditional IRA
- Roth IRA
- Other supported Alpaca account types

The system must therefore be designed to support **multiple accounts independently**.

Each account should have its own:

- Alpaca credentials/configuration
- Ticker allocation
- Allocation percentages
- Current positions
- Available cash
- Orders/trading activity

Do not hard-code the system around a single Alpaca account.

The configuration should make it easy to add or remove accounts without modifying the core trading logic.

---

# 4. Per-Account Ticker Allocation

Each account should have its own ticker allocation configuration.

For example:

### Account 1

```text
TQQQ 100%
```

### Account 2

```text
VTI 20%
VOO 20%
VUG 30%
VGT 15%
QQQ 15%
```

The percentages represent the desired allocation of the account's available investment capital among the configured tickers.

The configuration should be data-driven rather than hard-coded in Python logic.

Ideally, I should be able to add another account or change ticker percentages through configuration without changing application code.

The system should validate that the allocation percentages for each account are valid. For example, the total should normally equal 100%.

# 5. Buy/Sell Behavior

The system should support the following behavior based on the signals generated by `strategy.py`.

## Buy

When the strategy generates a buy signal:

1. Determine which accounts are configured to trade.
2. Get the available cash/buying power for each account.
3. Apply that account's ticker allocation percentages.
4. Calculate how much capital should be allocated to each ticker.
5. Submit the appropriate buy orders through Alpaca.

For example, if an account has $10,000 available and its configuration is:

```text
VTI 20%
VOO 20%
VUG 30%
VGT 15%
QQQ 15%
```

the target allocation would be approximately:

```text
VTI = $2,000
VOO = $2,000
VUG = $3,000
VGT = $1,500
QQQ = $1,500
```

The implementation must account for Alpaca's supported order types, fractional shares, minimum order requirements, available buying power, and other relevant broker constraints.

## Sell

When the strategy generates a sell/bearish signal:

- Sell everything in all the configured accounts and go to 100% cash.
